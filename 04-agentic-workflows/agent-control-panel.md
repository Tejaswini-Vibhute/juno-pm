## What Juno Is Doing

Flag risks

## Four Levers

**Stop Conditions** (Loop):

max_steps: 8, abort if fails 2 times in a row, hard timeout: 120s

**Structured Tool Outputs** (Tools):

Each tool Juno uses must return structured outputs with a status, result count, source identifier, and error code when applicable.

- **Slack Search:** Success → `status: success`, `message_count`, `message_ids`, `timestamps`, `thread_links`. Failure → `status: failed`, `error_code` (ACCESS_DENIED, TIMEOUT, API_ERROR). Zero results → `status: no_results`, requiring Juno to check other sources or flag missing evidence.
- **Jira Search:** Success → `status: success`, `issue_count`, `issue_keys`, `priorities`, `statuses`. Failure → `status: failed`, `error_code`. Zero results → `status: no_results`; Juno must not assume a duplicate does not exist without confirming search coverage.
- **Jira Ticket Creation:** Success → `status: created`, `jira_key`, `ticket_url`. Failure → `status: failed`, `error_code`. Juno must verify ticket creation before reporting completion.
- **Notion PRD:** Success → `status: success`, `page_id`, `version`, `last_updated`. Approved update → `status: updated`, `new_version`. Failure → `status: failed`, `error_code`. Updates require PM approval.
- **CRM Lookup:** Success → `status: success`, `account_count`, `account_ids`, `deal_stage`, `ARR`, `blockers`, `last_updated`. Failure → `status: failed`, `error_code`. Missing financial information must remain unknown.
- **Web Reviews:** Success → `status: success`, `review_count`, `review_ids`, `ratings`, `dates`. Failure → `status: failed`, `error_code`.
- **PM Approval:** Success → `status: approved` or `rejected`, `approver_id`, `request_id`, `timestamp`. Failure → `status: pending` or `expired`. No approval means no restricted action.

**Failure rule:** Juno must never interpret a failed tool call or empty response as proof that no issue exists. It should retry recoverable failures up to twice, then flag `NEEDS CLARIFICATION` or escalate to the human PM. All tool results must be verified before Juno takes further action.

**Confidence Thresholds** (Verification):

High confidence flags on its own. Medium confidence goes to a reviewer first. Low confidence waits for PM approval.

**North Star** (Context):

Always cite a source. Never make assumptions

## Rules of Engagement

**Agency Permission:**

Flag risks, don't approve without PM approval

**Access Control:**

Access only allowed docs

**Fallback Protocols:**

Three failed retries hands it back to PM instead of trying a fourth.

**Checkpoints:**

Every step needing legal approval
